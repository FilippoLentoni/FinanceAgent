# Proposal

## Why

Recommendations are only generated by a 09:05 timer on the developer desktop, and there is no supported way to ask for a fresh recommendation on demand. Individual decisions are stored centrally (`pd_…`), but nothing records a *run* — what triggered it, which inputs it consumed, which decisions and narratives it produced, and whether it failed — so the user cannot ask "show me the latest five recommendations" or trace an answer back to its run. We need a cloud-side trigger plus a queryable run log, and an hourly beta cadence so the plumbing can be verified within hours.

## What Changes

- Add an AWS Lambda **recommendation trigger** owned by FinanceAgent (beta only, behind a config flag). It calls the deployed LangGraph runtime with the existing read-only CI machine client, requesting PPO and the three classical recommendations (min variance, mean variance, scenario CVaR) for each configured saved paper portfolio. It never confirms decisions, changes holdings or trades.
- Trigger sources: an EventBridge Scheduler schedule (beta default `rate(1 hour)`, configurable, later reducible to once per morning) and **on-demand** invocation with the caller's own AWS credentials (`aws lambda invoke` / a small operator script). No browser token is needed by the caller.
- Add a DynamoDB on-demand table **recommendation runs**: one item per run with run id, trigger type, timing, status, per-method decision ids and statuses, consumed inputs (snapshot, news source day/window/checksum, model export and artifact checksum, portfolio revision), a bounded narrative excerpt, claim-check result and usage/cost. Items link to the full immutable decision records by `pd_` id rather than copying them.
- Duplicate protection: at most one scheduled run per portfolio per schedule window (conditional write) and a configurable daily run cap; on-demand runs always get a fresh run id but count toward the cap.
- Let the hosted agent answer "latest N recommendations/runs" (and filter by method or date) from the run log, and let the operator query it with a read-only script.
- The existing 09:05 desktop timer stays until the Lambda is verified in beta; retiring it is a follow-up.

## Capabilities

### New Capabilities
- `recommendation-runs`: cloud-triggered (scheduled and on-demand) generation of saved-portfolio recommendations, the durable run log that records each run's trigger, inputs, outputs and status, and how runs are queried by the agent and the operator.

### Modified Capabilities
None. Existing decision persistence, explanation, comparison and the daily report keep their requirements.

## Impact

- FinanceAgent: new Lambda, schedule, DynamoDB table and IAM in `infra/stacks/`; `config/beta.json` (`recommendation_trigger` block); agent routing for "latest N" questions plus a narrow read grant for the runtime role on the run table only; operator script; tests and docs.
- Permissions: the trigger Lambda may read the CI client secret and its SSM references and write its own table; the runtime role gains read-only Query on the run table. No platform, model or brokerage permissions change.
- Cost: hourly beta runs issue ~4 decisions per portfolio per hour through existing tools (Lambda + Nova Lite narration, `bedrock_explanations` budget, existing per-session caps); DynamoDB on-demand storage is negligible at this volume. Athena/Glue were rejected as more expensive for small point lookups.
- Formation rule unchanged: requests before 09:00 America/New_York fail closed for news-driven methods, and later requests reuse that morning's formation; hourly runs therefore re-value holdings against the same morning inputs and are recorded as such.
